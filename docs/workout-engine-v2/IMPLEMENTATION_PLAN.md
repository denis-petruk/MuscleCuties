## 4. Technical Resolutions for Part XIV Open Precision Items

To prevent implementation agents from inventing unsupported assumptions, the seven technical precision items identified in Part XIV of the specification are resolved as follows:

1. **Exercise-by-Exercise Muscle Contribution Map (Part XIV.1):**
  - Store explicit `ContributionKind` (`Direct = 1.0m`, `Indirect = 0.5m`, `Incidental = 0.0m`) in `ReviewedExerciseCatalogV020.json` and `ExerciseMuscleContribution` rows.
  - **Special Glute Rule:** Only `Direct` (`1.0m`) glute contributions count toward the Glute Specialization weekly direct-set target (`6–8`, `8–12`, `10–16`) and meaningful direct glute days (`>= 2` days/week). Compound movements where glutes are secondary (`0.5m`) count toward general systemic fatigue and secondary stimulus, never inflating direct glute specialization quotas.
  - **Special Rear-Delt & Arm Rule:** Rows (`HorizontalPull`, `VerticalPull`) credit `0.5m` indirect to rear delts and biceps; they never satisfy the mandatory weekly direct rear-delt (`Gate 51`) or direct biceps (`§6.2`) requirements.
2. **Time-Prediction Formula & Tolerance (Part XIV.2):**
  - `SessionDurationSeconds = WarmupGeneralSeconds + CooldownSeconds + FinisherSeconds + Sum(ExerciseSetupSeconds + WarmupSetSeconds + WorkingSetExecutionSeconds + InterSetRestSeconds)`.
  - Working-set execution time uses the upper bound of the prescribed repetition range (`MaximumRepetitions * SecondsPerRep * (UnilateralDoublesTime ? 2 : 1)`).
  - Straight-set rest is counted only *between* working sets (`(WorkingSets - 1) * RestSeconds`), never after the final set of an exercise.
  - Superset pairs share group rest (`SupersetGroupRestSeconds`) and a single combined transition allowance.
  - **Hard Constraint:** Predicted session duration must never exceed the user's configured `AvailableMinutes` (`PredictedMinutes <= AvailableMinutes`, `0` minutes upward overrun tolerance).
3. **Automatic Load Progression Without RIR (Part XIV.3):**
  - When `RirActual` is `null` and `TechniqueAcceptable` is `true`, a completed working set qualifies if `RepsCompleted >= PrescribedMaximumRepetitions` at `LoadKg >= PrescribedLoadKg`.
  - All prescribed working sets in the immutable `PlannedPrescriptionSnapshot` must be completed in two consecutive comparable exposures of the exact same `ExerciseId` before recommending an increase.
  - If `RirActual` is recorded and shows extreme effort below target (e.g., `RirActual = 0` when target is `3 RIR`), or if `TechniqueAcceptable == false`, the exposure does not qualify for a load increase.
  - For load reduction (`Gate 73`), two consecutive comparable completed sessions where completed reps fall strictly below `PrescribedMinimumRepetitions` trigger a recommendation to reduce to the next smaller equipment increment, regardless of whether `RirActual` was logged.
4. **72-Hour Pain Review & 10–15% Conservative Return Heuristic (Part XIV.4):**
  - A movement-provoked pain episode sets `ReassessmentDueAtUtc = ReportedAtUtc.AddHours(72)`.
  - Elapsed time (`NowUtc >= ReassessmentDueAtUtc`) only enables the contextual reassessment prompt; it **never** clears the restriction automatically (`WorkoutInjuryClearanceRule`).
  - Once the user explicitly marks the pain resolved and no other contraindication applies, the exercise enters a 2-session `ConservativeReturn` state: prescribed working load is set to `RoundToAvailableIncrement(PriorWorkingLoad * 0.875m)` (the midpoint of `10–15%` reduction, rounded down to the nearest valid equipment step) for `2` completed exposures before resuming normal double progression.
5. **Home-Equipment Catalog Completeness & Quarantine (Part XIV.5):**
  - Candidate bodyweight and band exercises (`Bodyweight Squat`, `Reverse Lunge`, `Split Squat`, `Floor Glute Bridge`, `Slider Leg Curl`, `Band Row`, `Band Chest Press`, `Band Curl`) are prepared in a structured draft manifest in Package B (`Task B10–B11`) with `ReviewStatus = PendingOwnerReview`.
  - The canonical planner strictly filters for `ReviewStatus == ApprovedWithConditions`. Until the owner approves the new candidate entries, limited-equipment profiles use the existing 59 reviewed exercises and disclose any unfilled movement pattern via `CatalogCoverageGuardTests` and `LimitationCodes`.
6. **Recovery-Mode State Transitions & Plan Immutability (Part XIV.6):**
  - Accepted weekly plans (`WorkoutPlanRecord` + `WorkoutPlanRevisionV02Record`) are immutable baseline prescriptions.
  - Daily readiness adaptations (`CycleReadinessPrescriptionRule`, `-1` optional accessory set) write a per-occurrence overlay (`WorkoutCycleReadinessOccurrenceRecord`) linked to the `WorkoutDayId` and `CheckInRevision` without creating a new weekly plan proposal or requiring **Apply Plan**.
  - Midweek schedule/preference changes create a `WorkoutPlanProposalV02Record` preview and leave the active plan untouched until the user taps **Apply Plan**.
7. **Provenance of Decisions 1–48 (Part XIV.7):**
  - Historical Gate numbers `1–48` are not fabricated. All pre-Gate-49 requirements are permanently indexed under stable identifiers `REQ-001` through `REQ-033` and `REQ-052` through `REQ-063` in Section 3 above.
