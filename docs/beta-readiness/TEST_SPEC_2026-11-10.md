# Test specification — pre-Beta (2026-11-10)

Owner-gated: this document describes tests only. Nothing under `tests/` was created or edited by the QA worktree.

## 1. Safety / cycle policy

1. **DK1 dose decision table** (`CycleReadinessPrescriptionRule`)
   - current check-in with < 7 h sleep -> exactly one optional accessory set removed;
   - lighter/easier readiness band -> reduced dose;
   - routine symptoms -> reduced dose;
   - no current check-in, or a check-in with >= 7 h sleep and a normal band -> full dose;
   - legacy persisted rows with `phaseFeeling`/`repeatedFeeling` are not treated as new evidence.
2. **DK2 legacy injury rows** (`PostgresWorkoutPlanReconciler`)
   - seed a day with `IsOptional = true`, `InjuryRestorationRequiredFromDate = clearance + 7`;
   - reconcile on a later day with no injury edit -> row becomes required;
   - a day bound to a completed session stays excluded from suppression (regression for F02).
3. **Cycle policy version**: `MC-CYCLE-READINESS-0.2` approval must still match; a bump to 0.3 requires a new owner-approved `PlanningReleaseApproval` record.

## 2. Check-in / Health

4. **Pre-fill (DK4)**: typed sleep is not overwritten by a Health refresh; unknown sleep stays unset (not 0 h); "apply suggestion" ignores a 0 rating.
5. **Window/coverage (DK5)**: averages over seven completed days; < 4 days with data -> no calorie adjustment; overlapping sleep samples merge without double counting (`MergedHours`), including samples crossing midnight.
6. **Synthetic provider (DK8)**: only selected when `MC_SYNTHETIC_HEALTH=1` and only in Debug.

## 3. Workout and nutrition

7. **F01**: bodyweight exercise with no history -> `LoggedWeightText` is a real "0" and advances; weighted lift with no history -> empty box, explicit weight required, no silent 0 kg log.
8. **F05**: consumed totals from meals and diary agree on Today and Nutrition; hydration-only row does not mask food; soft-deleted rows excluded; tenant isolation.
9. **F06**: state label mapping for planned / in progress / completed matches between Today and Workouts, EN and RU.
10. **F04**: after finish, the Workouts tab issues exactly one overview call and clears the loading state; no spinner outlives an idle freshness gate.

## 4. Localization and UI guards

11. **Catalog parity**: every key exists in EN and RU; format arguments match; every status code emitted by the server resolves to a key; no raw enum (`Hiit`, `RockClimbing`, `Running`) is bound.
12. **XAML resource-key guard**: every `StaticResource` and `loc:LocalizedText` key used by a changed page resolves at runtime (the ProfilePrivacyPage crash was not caught by compilation).
13. **RuntimeText freeze**: no new entries; existing entries removed as their code paths ship.

## 5. Contract / compatibility

14. Old JSON payloads deserialize when additive fields are absent (defaults preserved).
15. A client running the previous build ignores new state fields and still renders.
